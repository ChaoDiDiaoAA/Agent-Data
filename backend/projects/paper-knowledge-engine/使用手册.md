# 论文知识引擎使用手册

本手册描述共享引擎的确定性资料流程。paper 方向库必须显式选择，状态、Archive、Evidence、PDF 根和 Vault 根彼此隔离，不生成 LLM 内容。

## 启动与菜单

先打开 PowerShell，切换到项目目录，再启动 Bun 菜单。可以直接复制执行：

```powershell
cd D:\agent-data\backend\projects\paper-knowledge-engine
bun src/cli.ts
```

启动前，终端提示符应显示：

```text
PS D:\agent-data\backend\projects\paper-knowledge-engine>
```

启动后先显示方向选择；输入 `1` 选择 FSD，输入 `0` 退出，留空不会自动选择：

```text
论文知识引擎（Bun CLI）
请选择方向库：
1. FSD 论文知识库
2. Agent Engineering
3. Multi-Agent Engineering
4. LLM Post-Training（大模型后训练知识库）
5. Agent Tool & RSI（含 LLM 工具后训练）
6. Agent & LLM Context
7. Skill & Prompt Engineering
8. Agent Memory（智能体记忆知识库）
0. 退出
```

后续新增方向会自动列出：在 `config/<libraryId>/` 配齐 `library.yaml`、`query-matrix.yaml`、`paper-policy.yaml`、`categories.yaml`。如需显式选择并跳过选库步骤，在同一目录执行：

```powershell
bun src/cli.ts --library fsd
```

选择 Agent Engineering 后菜单为：

```text
1. 查看来源配置
2. 运行当前任务
3. 运行周任务
4. 运行 Backfill
5. 导入本地资料
6. 发布或恢复 Evidence
7. 对账来源 Archive 与 Evidence
8. 查看任务配置
9. 准备或修复 OpenCLI
10. 切换方向库
0. 退出
```

它不会出现 MinerU、导入 PDF 或解析论文选项。Research 的显式命令示例：

```powershell
bun src/cli.ts --library agent-engineering source-config --format json
bun src/cli.ts --library agent-engineering run-task --mode current
bun src/cli.ts --library agent-engineering run-task --mode backfill --from 2026-01-01 --to 2026-09-07
bun src/cli.ts --library agent-engineering import-source --path D:\research\agent-notes --kind local-artifact --track agent-loop
bun src/cli.ts --library agent-engineering reconcile
```

`import-source` 只接受绝对路径和 `local-artifact`，资料先进入 research selection 和 Archive，不直接写 Evidence。Research 的 `candidates`、`accepted`、`newVersions`、`archived`、`published` 都按唯一 `sourceId/versionId` 计数，同一来源命中多个 Track 不重复计数；不会收集 benchmark 数据集、排行榜或单个结果。

本手册后续所有 `bun` 命令均在上述项目目录执行，不是在 PDF 目录或 Obsidian 目录执行。独立工作树验证时，改为切换到该工作树内的项目根。历史迁移与恢复证据见 [迁移记录](docs/superpowers/plans/2026-09-05-real-migration-progress.md)。

LLM Post-Training 的稳定标识为 `llm-post-training`，显示名为 `LLM Post-Training（大模型后训练知识库）`。它使用与其他 paper 库相同的菜单；查看配置、首期小批量、恢复、发布和历史 PDF 导入的准确命令见 [后训练库操作说明](docs/llm-post-training/operations.md)。

Agent Tool & RSI 的稳定标识为 `agent-tool`，显示名为 `Agent Tool & RSI（含 LLM 工具后训练）`。它使用与其他 paper 库相同的菜单，18 个 Track 覆盖 Agent Tool、LLM 工具后训练和 RSI；Current 上限 270，Weekly 增量上限 12，首期手动运行。

Agent Memory 的稳定标识为 `agent-memory`，显示名为 `Agent Memory（智能体记忆知识库）`。它使用与其他 paper 库相同的菜单，20 个 Track 覆盖运行时记忆、RSI 记忆和 LLM 后训练记忆；Current 上限 200，Weekly 增量上限 20，首期手动运行。详细命令见 [Agent Memory 操作说明](docs/agent-memory/operations.md)。

Skill & Prompt Engineering 的稳定标识为 `skill-prompt-engineering`，显示名为 `Skill & Prompt Engineering（技能与提示词工程知识库）`。它从 `2025-01-01` 起收录 arXiv 论文，Current 上限 200，Weekly 增量上限 20，首期手动运行。`pe-*` 是 Prompt Engineering，`se-*` 是 Skill Engineering，覆盖技能获取、组合、迁移、自我演化（自进化）和评测；`se-rsi` 只收录明确以 Skill 为改进对象并具备递归迭代机制的论文。详细命令见 [Skill & Prompt Engineering 操作说明](docs/skill-prompt-engineering/operations.md)。

```text
论文知识引擎（Bun CLI）
当前方向库：FSD 论文知识库（fsd）
=========================
1. 查看 MinerU 配置
2. 运行当前任务
3. 运行周任务
4. 导入并解析本地 PDF
5. 解析指定论文
6. 发布或恢复 Evidence
7. 对账 PDF 与 Evidence
8. 查看任务配置
9. 检查 arXiv 网络
10. 准备或修复 OpenCLI
11. 切换方向库
0. 退出
```

菜单由 Bun 自身处理；不需要前端。菜单 `9` 从同一 Bun/OpenCLI 运行时检查 arXiv 网络，菜单 `11` 返回选库界面，后续任务使用新方向的配置和状态目录。未知方向库会报错，不会自动回退到 FSD。直接执行方向命令必须指定 `--library`；通用脚本也需显式传入，例如 `bun run task:current --library fsd`。查看全部命令使用 `bun src/cli.ts --help`。

## 配置和任务日期

只需维护三类配置：

- `config/engine.yaml`：arXiv 请求边界、MinerU 解析参数、API 启动/任务超时、运行时清理和 Evidence v3 契约。
- `config/machine.local.yaml`：数据、备份、独立 PDF、Vault 根目录，PDF 的 `network.http_proxy`，可选的 OpenCLI 路由，以及本机 MinerU 安装、模型和 GPU。本地 MinerU API 保持直连；详见 [配置说明](config/README.md)。
- `config/fsd/library.yaml`：方向身份、名称、日期、当前配额和周调度。
- `config/fsd/query-matrix.yaml`：8 个检索方向，各含提交/更新日期模式，共 16 个分片。
- `config/fsd/paper-policy.yaml`：论文纳入、排除条件和分类优先级。
- `config/fsd/categories.yaml`：12 个 PDF 分类目录映射，不代表有 12 个独立检索任务。
- `config/llm-post-training/library.yaml`：后训练方向身份、`2026-01-01` 起点、48 小时重叠窗口、Current 180 和 Weekly 18。
- `config/llm-post-training/query-matrix.yaml`：18 个 Track，各含 submitted/updated，共 36 个分片。
- `config/llm-post-training/paper-policy.yaml`：从标题和摘要判断模型对象词与后训练信号，不以 Track 标签替代证据。
- `config/llm-post-training/categories.yaml`：18 个 Track 的 PDF 目录映射及 `99-Unclassified` 兜底。
- `config/agent-tool/library.yaml`：Agent Tool & RSI 身份、`2026-01-01` 起点、48 小时重叠窗口、Current 270 和 Weekly 12。
- `config/agent-tool/query-matrix.yaml`：18 个工具、后训练和 RSI Track，各含 submitted/updated，共 36 个分片。
- `config/agent-tool/paper-policy.yaml`：要求工具能力证据；后训练 Track 还需训练证据，RSI Track 还需明确改进循环。
- `config/agent-tool/categories.yaml`：18 个 Track 的 PDF 目录映射及 `99-Unclassified` 兜底。
- `config/agent-memory/library.yaml`：Agent Memory 身份、`2026-01-01` 起点、48 小时重叠窗口、Current 200 和 Weekly 20。
- `config/agent-memory/query-matrix.yaml`：20 个记忆、RSI 和后训练记忆 Track，各含 submitted/updated，共 40 个分片。
- `config/agent-memory/paper-policy.yaml`：要求模型对象与记忆机制证据；后训练 Track 不要求出现完整 Agent，RSI Track 还需明确改进循环。
- `config/agent-memory/categories.yaml`：20 个 Track 的 PDF 目录映射及 `99-Unclassified` 兜底。
- `config/skill-prompt-engineering/library.yaml`：Prompt/Skill 身份、`2025-01-01` 起点、48 小时重叠窗口、Current 200 和 Weekly 20。
- `config/skill-prompt-engineering/query-matrix.yaml`：10 个 Prompt、9 个 Skill Track，各含 submitted/updated，共 38 个分片。
- `config/skill-prompt-engineering/paper-policy.yaml`：区分 Prompt、Skill 和 Skill RSI 的标题摘要证据，排除金融 RSI 与无工程信号论文。
- `config/skill-prompt-engineering/categories.yaml`：10 个 Prompt 分类、9 个 Skill 分类及 `99-Unclassified` 兜底。

菜单 2 的新任务从方向配置的 `start_date` 到当天；成功水位不会缩短当前任务的开始日期。菜单 3 根据上次成功水位和 `overlap_hours` 增量处理。显式 `--from`、`--to` 会覆盖默认日期，仅在需要时使用。

```text
bun src/cli.ts --library fsd run-task --mode current
bun src/cli.ts --library fsd run-task --mode current --limit 1
bun src/cli.ts --library fsd run-task --mode weekly
bun src/cli.ts --library fsd harvest-plan --mode current --format json
```

发现候选数不等于下载数；硬过滤、库内去重和配额完成后才固定选篇并下载。失败后再次执行相同任务会优先恢复其检查点、固定选篇和已下载 PDF。

## 本地解析

```text
bun src/cli.ts --library fsd opencli-prepare
bun src/cli.ts --library fsd mineru-config --format json
bun src/cli.ts --library fsd import-local --path PDF_FILE_OR_FOLDER --preview
bun src/cli.ts --library fsd import-local --path PDF_FILE_OR_FOLDER
bun src/cli.ts --library fsd parse-local --base-id BASE_ID --reparse
```

将大写占位符替换为真实路径或论文 ID。交互导入会先预览并确认。

每次解析操作启动一个任务级 MinerU API，同一任务的论文共享该服务；完成或中断后回收。再次恢复会建立新的任务级服务。模型和权重仍来自本地部署。

`pipeline_batch_ratio: 1` 控制 Pipeline 内部推理批量；`max_concurrency: 1` 控制请求并发；`processing_window_size: 1` 控制处理窗口页数。VLM 批量参数只在 VLM 模式生效。完整参数说明见 [配置说明](config/README.md)。

## 失败恢复与维护

### arXiv 网络探针与路由

浏览器能访问 [arxiv.org](https://arxiv.org/) 只说明浏览器路径可用，不代表 Bun/OpenCLI 子进程能访问 `arxiv.org` 或 `export.arxiv.org` API。先运行同一运行时探针：

```powershell
bun src/cli.ts --library fsd arxiv-check --format json
```

如果直连探针返回 `reachable`，可以只让 OpenCLI 绕过代理，PDF 仍走原代理：

```yaml
network:
  http_proxy: "http://127.0.0.1:7897"
  opencli_proxy_mode: direct
  arxiv_api_base: "https://arxiv.org/api/query"
```

如果 `direct` 返回 `unreachable` 或超时，删除 `opencli_proxy_mode` 和 `arxiv_api_base`（不要写空字符串或 `null`），会恢复有 `http_proxy` 时的 `configured` 行为。当前这台机器的真实 Bun 探针中，现有代理路线和直连路线都报告 `unreachable`，因此暂不把 `config/machine.local.yaml` 切到直连；浏览器首页可用不能替代这个结论。

`ARXIV_TRANSPORT_UNAVAILABLE` 表示尚未收到 HTTP 响应的连接/传输失败；`ARXIV_CAPACITY_LIMITED` 仍只表示 HTTP 429，二者不要混用。修改路由后重新执行同一 current 任务即可恢复原 run，已完成分片会跳过，不要删除数据库或 checkpoint。

### arXiv 限流与冷却

`ARXIV_CAPACITY_LIMITED` 表示检索请求被限流，`ARXIV_COOLDOWN_ACTIVE` 表示已有冷却尚未结束；不是 MinerU 解析失败。终端和任务结果显示北京时间的截止时间，结果中的 `retryNotBefore` 保留 UTC，供程序读取。服务端原始响应与代理细节不会直接输出到任务结果。

冷却结束后重新启动 `bun src/cli.ts`，选择原方向，再执行同一模式（当前任务选 `2`，周任务选 `3`）。保持配置与限额不变、不加新日期覆盖，程序优先恢复失败 run，跳过已完成分片。发现阶段失败不要使用菜单 `6`（该项只恢复 Evidence 发布）。

冷却默认由 `config/engine.yaml` 的 `arxiv.capacity_cooldown_seconds` 控制，不代表上游承诺届时恢复。若仍被限流，请停止连续尝试，不删除数据库或检查点，不通过缩短间隔重试。

解析成功而发布失败时，用原 run ID 单独恢复发布：

```text
bun src/cli.ts --library fsd evidence-publish --run-id RUN_ID
bun src/cli.ts --library fsd reconcile
```

Windows 上如果 Evidence 发布在 journal、目标文件或 receipt 的替换步骤遇到短暂文件锁，程序会对同一文件系统的替换做有限次重试；不会先删除目标文件。每个 run 还有独立的 publication lock，避免两个发布者同时写同一组事务文件。

如果故障留下 `publication-journal.json` 和 `publication-journal.json.new`，恢复会分别校验两份快照。只有两份绑定相同且临时快照是持久快照的完整前缀扩展时才会继续；不一致时会保留两份文件并报告 `EVIDENCE_CONFLICT`，不要手动删除或覆盖它们。

例如原 run `54fd8ee4-2f5c-4554-a169-0295b83282dd` 在 Evidence 发布阶段失败，可直接重试：

```powershell
bun src/cli.ts --library fsd evidence-publish --run-id 54fd8ee4-2f5c-4554-a169-0295b83282dd
```

恢复使用已有 Archive，不会重新下载 PDF 或重新运行 MinerU；只有 Archive 校验本身无效时才需要回到前置阶段。若仍出现 `EVIDENCE_IO`，先关闭可能占用数据目录中文件的编辑器/索引工具后重试；如符合安全策略，可将数据根目录加入杀毒实时扫描和索引排除项，但不要为了程序运行而关闭安全控制。

不要删除 `runs/`、`operations/` 或 Archive 来解决恢复错误。进程安全记录位于 `operations/locks/processes/`；通过 CLI 检查精确记录路径：

```text
bun src/cli.ts --process-supervisor --inspect RECORD_PATH
bun src/cli.ts --process-supervisor --resolve RECORD_PATH
```

`--resolve` 仅在 owner 已不存在、且 `cleanupConfirmed` 为 `true` 时移除该条记录。

离线迁移和重建先只生成计划：

```text
bun src/cli.ts --library fsd archive-migrate --dry-run --format json
bun src/cli.ts --library fsd library-migrate --dry-run --format json
bun src/cli.ts --library fsd vault-rebuild --dry-run --format json
```

这些命令不自动保存计划文件。保存并审查输出后，apply 必须提供同一计划文件和 SHA-256；详见 CLI 帮助和已确认迁移计划。

## 周调度与验证

FSD 周任务名称为 `paper-knowledge-engine-fsd-weekly`，日期、周期和时区读取方向配置。先确认引擎路径已切换且时区匹配，再安装调度：

```text
bun src/cli.ts --library fsd schedule-config --format json
bun run schedule:install
bun run schedule:status
bun run schedule:uninstall
```

定时执行由 Bun runner 承接。

LLM Post-Training 首期不注册 Windows 或 Codex 定时任务；其 `weekly_schedule.enabled: true` 只为保留手动 `weekly` 入口，不要调用省略 `--library` 的 package 快捷脚本或默认按 FSD 装载配置的 scheduler installer。定向验证使用隔离临时根：

```powershell
bun test --timeout 30000 tests/llm-post-training-paper-library.test.ts tests/llm-post-training-integration.test.ts tests/multi-agent-paper-library.test.ts tests/research-library-config.test.ts tests/cli-menu.test.ts tests/configured-task-limits.test.ts tests/research-fsd-isolation.test.ts
```

Skill & Prompt Engineering 同样不安装 Windows 或 Codex 定时任务；其 `weekly_schedule.enabled: false` 只保留每 4 周周一的手动任务描述，增量上限为 20。验证 Prompt/Skill 分类、RSI 边界和 38 个分片：

```powershell
bun test --timeout 30000 tests/skill-prompt-engineering-paper-library.test.ts
```

```text
bun install --frozen-lockfile
```
