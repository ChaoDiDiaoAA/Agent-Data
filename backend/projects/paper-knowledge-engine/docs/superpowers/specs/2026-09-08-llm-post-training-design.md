# 大模型后训练知识库目标方案

- 设计日期：2026-09-08
- 状态：用户已于 2026-09-08 确认目标方案；实施计划已编写，尚未实施
- 实施计划：[大模型后训练知识库实施计划](../plans/2026-09-08-llm-post-training-implementation.md)
- 方向库标识：`llm-post-training`
- 显示名称：LLM Post-Training（大模型后训练知识库）
- 适用引擎：现有 `paper-knowledge-engine`
- 本轮交付：目标、范围、主题体系、接入方式、建设阶段与验收标准

## 1. 总体目标

建立一个围绕“大模型在预训练之后如何获得目标能力和行为”的独立论文知识库，系统覆盖数据、监督微调、偏好优化、强化学习、奖励与验证、推理、蒸馏、Agent 能力训练、训练工程和评测。

知识库应帮助使用者沿着“问题 → 方法 → 训练条件 → 实验证据 → 适用边界”理解论文，能够比较不同方案，而不仅按算法名称查找 PDF。

首期建设可追溯、可恢复的论文资料层；综合知识由人工阅读和确认后形成。知识引擎继续采用确定性处理，不调用 LLM 生成摘要、方法比较或训练建议。

### 1.1 需要支持的研究问题

1. 一个目标能力更适合通过 SFT、偏好优化、强化学习还是蒸馏获得？判断依据是什么？
2. 指令数据、偏好数据、推理轨迹和环境交互数据分别如何构造、筛选、混合和验证？
3. 奖励来自人类、模型、规则还是环境？奖励的可靠性和可利用漏洞如何影响训练？
4. 训练效果对基座模型、数据规模、采样策略、算力预算和超参数有何依赖？
5. 怎样训练多轮交互、工具调用、代码执行与长时程 Agent 能力？
6. 后训练是否导致遗忘、奖励投机、模式收缩、过度拒答或其他能力退化？
7. 论文报告的提升来自训练、推理时计算量、数据污染还是评测方式变化？如何区分？
8. 方法在其他模型、任务、语言或模态上是否有可复核的迁移证据？

这些是后续阅读与综合的目标，不表示首期引擎会自动回答这些问题。

## 2. 建设方式选择

| 方式 | 收益 | 代价与边界 | 结论 |
|---|---|---|---|
| 新增独立 paper 方向库，复用现有引擎 | 独立主题、状态和 Vault；沿用成熟处理链 | 自动来源限定为论文，综合知识需要人工确认 | 推荐 |
| 合并进 Agent Engineering 的若干 Track | 少维护一个方向库 | 通用对齐、推理训练和训练系统难以放入 Agent 工程边界 | 不采用 |
| 新建多来源 research 库 | 可以组织论文、框架文档与代码版本 | 增加来源策略、适配、版本和发布维护成本 | 暂不采用 |

新增方向采用 `library_kind: paper`，与 `fsd`、`agent-engineering`、`multi-agent-engineering` 并列。自动发现使用 OpenCLI/arXiv，继续保留用户显式指定的本地 PDF 导入。

## 3. 领域范围与边界

### 3.1 后训练的工作定义

本库以预训练语言模型及其多模态扩展为对象，研究通过后续学习改变模型参数、可训练适配器或相关奖励/验证模型，获得指令遵循、偏好对齐、推理、工具使用和特定领域能力的方法；同时收录直接服务于这些训练方法的数据、理论、系统与评测研究。

不要求所有纳入论文都训练主模型：奖励模型训练、后训练数据质量、训练稳定性分析和评测方法研究，也可以独立构成本库主题。

“后训练”不等于固定串行配方。InstructGPT 提供监督微调与人类反馈训练的代表路径；DPO 提供直接从偏好数据优化语言模型的路径；DeepSeek-R1 展示了强化学习促进推理能力的研究路径。主题组织应允许不同阶段组合，不能强制每种方法都先经过相同的 SFT 和奖励模型训练步骤。[InstructGPT](https://arxiv.org/abs/2203.02155)、[DPO](https://arxiv.org/abs/2305.18290)、[DeepSeek-R1](https://arxiv.org/abs/2501.12948)

### 3.2 收录原则

- 主要研究对象是语言模型、以语言为核心的多模态模型，或其奖励/验证模型。
- 主要贡献与后训练方法、训练数据、训练系统、理论分析或评测协议直接相关。
- 论文能够提供可引用的方法描述、理论分析或实验依据；综述可作为导航资料，但不代替原始证据。
- 数据集和训练框架论文可以收录，资料层保存论文及来源链接，不自动下载训练数据、模型权重或仓库。
- 应用论文只有在训练方法、数据设计或评测方面有明确研究贡献时才纳入；普通“微调模型完成某应用”的描述不自动等同于后训练方法研究。

### 3.3 交叉主题的归属

| 主题 | 本库收录边界 | 相邻领域 |
|---|---|---|
| 预训练与继续预训练 | 收录与后训练阶段组合、对比、能力保持直接相关的部分 | 通用预训练语料、架构和缩放研究不单独展开 |
| Prompt、RAG、Memory | 训练检索、记忆使用或上下文利用能力的方法 | 纯提示词、检索配置和运行时记忆管理属于 Agent 工程 |
| 工具调用与 Agent | 轨迹监督、交互式 RL、工具执行反馈和长时程信用分配 | Harness、Runtime、权限和调度属于 Agent Engineering |
| Multi-Agent | 通过多 Agent 交互、对抗或协作产生训练信号，或训练协作策略 | 仅讨论拓扑、通信和编排属于 Multi-Agent Engineering |
| 推理时计算 | 为训练提供数据/奖励，或明确评估训练与推理预算之间的关系 | 纯搜索、投票、采样或提示增强不作为核心主题 |
| 多模态 | 视觉/音频/视频语言模型的指令微调、对齐、奖励和推理训练 | 纯扩散模型训练或无语言模型关联的视觉 RL 暂不展开 |
| 参数高效微调 | 语言模型后训练中的适配器、低秩更新和量化微调 | 纯推理量化、部署压缩不单独纳入 |

同一篇论文满足多个库的规则时，允许各库独立保存。首期不建设跨库去重、共享数据库或自动关联机制；人工知识页可保留论文 arXiv ID 和相关库的说明。

## 4. 主题体系：18 个 Track

以下 Track 是检索与分类入口，允许同一论文命中多个主题。表中顺序用于导航；主分类沿用共享选篇器的配额分配结果，不宣称是自动识别出的“论文主要贡献”。

| Track ID | PDF 分类目录 | 研究内容 |
|---|---|---|
| `pt-foundations` | `01-PT-Foundations` | 后训练定义、阶段组合、学习目标、理论假设、方法谱系及综述 |
| `pt-sft` | `02-PT-SFT` | 指令微调、多轮监督、示范学习、损失掩码、训练目标与配方 |
| `pt-data-curation` | `03-PT-Data-Curation` | 数据质量、去重、混合、难度、课程、标注一致性、污染和许可问题 |
| `pt-synthetic-data` | `04-PT-Synthetic-Data` | 合成指令、合成偏好、推理轨迹生成、自我改进、拒绝采样与数据验证 |
| `pt-reward-modeling` | `05-PT-Reward-Modeling` | 偏好奖励、结果奖励、过程奖励、验证器训练、校准、泛化和奖励利用漏洞 |
| `pt-preference-optimization` | `06-PT-Preference-Optimization` | DPO 等直接偏好优化目标、离线偏好学习、参考策略及迭代数据更新 |
| `pt-policy-optimization` | `07-PT-Policy-Optimization` | PPO、GRPO 等策略优化，优势估计、KL、探索、采样分布和离策略修正 |
| `pt-verifiable-rewards` | `08-PT-Verifiable-Rewards` | 可验证奖励 RL、数学与代码验证、规则/环境奖励、稀疏奖励和奖励组合 |
| `pt-reasoning` | `09-PT-Reasoning` | 推理轨迹训练、长推理、自我验证、训练与推理预算关系、推理能力迁移 |
| `pt-distillation` | `10-PT-Distillation` | 响应/轨迹/策略蒸馏、教师选择、学生能力保持、在线蒸馏和迁移成本 |
| `pt-tool-agent` | `11-PT-Tool-Agent` | 工具调用、多轮交互、环境反馈、Agent RL、轨迹信用分配与训练环境 |
| `pt-multimodal` | `12-PT-Multimodal` | 多模态指令微调、偏好对齐、奖励、可验证任务及跨模态推理训练 |
| `pt-safety-alignment` | `13-PT-Safety-Alignment` | 人类/AI 反馈对齐、安全训练、拒答与有用性权衡、鲁棒性、多目标与个性化偏好 |

| `pt-efficient-tuning` | `15-PT-Efficient-Tuning` | LoRA、QLoRA、适配器、可训练参数选择、显存和训练成本权衡 |

### 4.1 防止概念混用

- 反馈来源、学习目标、优化算法、参数更新方式与能力目标应分别记录。例如，人类反馈是信号来源，DPO 是偏好优化方法，GRPO 是策略优化算法，LoRA 是参数更新方式，工具使用是能力目标。
- `pt-reward-modeling` 研究奖励/验证器本身；`pt-verifiable-rewards` 研究如何用可验证反馈训练策略；`pt-policy-optimization` 研究策略更新机制。允许交叉标签。
- `pt-synthetic-data` 研究数据如何生成；`pt-distillation` 研究教师知识或行为如何迁移到学生。合成数据训练学生可以同时命中两者。
- `pt-reasoning` 关注能力形成；`pt-evaluation` 关注如何可靠证明能力变化。

GRPO 在 DeepSeekMath 中作为 PPO 的变体提出；过程监督与结果监督的比较可由 Let's Verify Step by Step 引入；QLoRA 则为量化基座上的低秩适配提供参考。这些区别支持上述多维分类，不应把它们放在同一层级排成互斥选项。[DeepSeekMath](https://arxiv.org/abs/2402.03300)、[Let's Verify Step by Step](https://arxiv.org/abs/2305.20050)、[QLoRA](https://arxiv.org/abs/2305.14314)

## 5. 来源、时间范围与检索策略

### 5.1 来源策略

- 自动来源：OpenCLI/arXiv 论文及 arXiv 承载的技术报告。
- 手工来源：通过现有 `import-local` / `parse-local` 处理用户指定的本地 PDF。
- 博客、官方文档、课程、代码仓库和模型卡只作为人工阅读的外部参考，首期不接入自动采集。
- 自动任务经过规则筛选后再下载 PDF，继续保留 arXiv 身份、版本、提交时间和更新时间。

### 5.2 日期策略

默认沿用现有方向库的自动起点 `2026-01-01`，每个 Track 同时查询 `submitted` 和 `updated`，共 36 个检索分片。

按照当前共享筛选器，满足时间条件的是：首次提交不早于起点，或在起点之后发生晚于首次提交的更新。旧论文的新版可能进入自动结果，但“更新”不等于“重要版本”，引擎不自动判断修订的重要性。

为了支持完整学习路线，建议另行整理 20–30 篇历史基础论文候选清单，人工检查是否已收录，再通过本地 PDF 入口补充。日期之前的经典论文不会因为被写入候选清单就自动绕过日期规则，也不通过伪造日期或修改全库起点强行进入自动流程。

基础候选的起始样例是 InstructGPT、DPO、Let's Verify Step by Step、QLoRA、DeepSeekMath 和 DeepSeek-R1；上述原始论文链接已在第 3、4 节列出。这是拟议阅读入口，不是已入库清单或完整文献调查。

手工导入必须保留真实来源信息，且不推进 arXiv 自动任务的水位。历史论文覆盖与自动追踪覆盖分开记录。

### 5.3 检索组织

以 `cs.CL`、`cs.LG`、`cs.AI` 为基础分类，按主题增加 `cs.DC`、`cs.CV`、`cs.SD`、`cs.SE`、`cs.MA` 或 `stat.ML`；不把所有分类统一加到每个 Track。

每条查询包含“模型对象”与“具体后训练主题”两部分，使用明确的字段、括号和 Boolean 组合，避免把大量主题词串成必须同时出现的查询。例如，SFT Track 可从以下未实测查询开始校准：

```text
(ti:"language model" OR abs:"language model" OR ti:LLM OR abs:LLM)
AND
(ti:"instruction tuning" OR abs:"instruction tuning"
 OR ti:"supervised fine-tuning" OR abs:"supervised fine-tuning")
```

这是查询构造示例，不是可直接冻结的最终词表。完整查询矩阵应在实施阶段以真实标题/摘要样本验证；查询词、分类、筛选词应一起检查，避免查询能命中而规则将其全部拒绝。

## 6. 自动筛选与质量控制

### 6.1 复用现有规则契约

首期不新增后训练专用筛选模块，沿用当前规则结构：

1. `ai_technique_terms` 表达模型对象，例如 `large language model`、`language model`、`LLM`、`vision-language model`，配合 `term_variants` 处理常见变体。
2. `program_structure_terms: []`，避免普通结构词绕过模型对象要求。
3. `engineering_task_terms` 表达后训练信号，例如 `post-training`、`instruction tuning`、`supervised fine-tuning`、`preference optimization`、`reward model`、`RLHF`、`GRPO`、`distillation` 等；最终取值由样本校准决定。
4. 继续校验 arXiv 身份、日期、已启用 Track 和明确排除规则。

这些字段名称来自共享 paper 契约；本库赋予其方向词表，不为重新命名字段扩展全局 Schema。

模型对象词与后训练信号词必须从标题和摘要获得。仅有 Track 标签，或正文之外的调用方附加标签，不能作为纳入证据。避免用 `training`、`optimization`、`agent` 等宽泛词独立满足后训练条件，也不直接把整个 Track ID 当作主题判断。

### 6.2 规则能力的实际边界

当前筛选器判断词语共现，不能判定“主要贡献”“只在相关工作中提到”或“该论文可靠”。因此第 3 节是收录目标；本节规则只是自动近似，不能宣称完全实现语义筛选。

筛选报告应保留通过/拒绝原因和匹配词。人工抽样发现问题后，先调整方向查询和词表，并增加对应回归样例；如果共享规则确实无法表达所需边界，再单独提出引擎改进方案。

`reward hacking`、`forgetting`、`jailbreak`、`distribution shift` 等可能正是本库研究的问题，不应因为包含风险词就全局排除。

### 6.3 正反例要求

- 正例：每个 Track 至少一个清晰的标题/摘要样例，并覆盖连字符、缩写和单复数变体。
- 负例：普通游戏/机器人 RL、纯预训练、纯提示优化、纯推理加速、无训练内容的 Agent 编排、普通应用微调描述、缩写同名歧义等。
- 边界例：仅研究奖励模型、后训练数据、稳定性理论或评测方法的论文；包含后训练研究的多模态论文；2026 年前论文的真实更新版本。
- 对当前规则难以区分的“相关工作提及”等情况，记录误收限制，不编造能够通过的语义验收承诺。

## 7. 接入现有系统

### 7.1 四文件配置

方向目录为 `config/llm-post-training/`，只新增共享 paper 契约要求的四个文件：

| 文件 | 职责 |
|---|---|
| `library.yaml` | 身份、显示名、日期、总配额、Track 配额与调度字段 |
| `query-matrix.yaml` | 18 个 Track 的检索表达式、arXiv 分类和日期模式 |
| `paper-policy.yaml` | 模型对象词、后训练信号词、变体、排除规则和分类优先级 |
| `categories.yaml` | Track 到 PDF 分类目录的映射与兜底目录 |

新增方向沿用共享 CLI 菜单和 `current` / `weekly` 任务模式，不接入 research 的 `source-policy.yaml`、`topic-taxonomy.yaml`、`import-source` 或 `backfill`。

### 7.2 资料处理链

```text
llm-post-training 四文件配置
  → OpenCLI/arXiv 发现
  → 合并命中、规则筛选、冻结选篇
  → PDF 下载
  → MinerU 本地解析
  → Archive v2
  → Evidence v3 与现有索引
```

继续复用去重、版本保留、检查点、网络冷却、重试、任务恢复、MinerU 生命周期和 Evidence 原子发布。

### 7.3 命名与路径

| 用途 | 目标路径 |
|---|---|
| 共享引擎 | `D:/agent-data/backend/projects/paper-knowledge-engine` |
| 方向配置 | `D:/agent-data/backend/projects/paper-knowledge-engine/config/llm-post-training` |
| PDF 原件 | `D:/paper/paper-knowledge-engine/llm-post-training` |
| 运行数据 | `D:/agent-data/data/paper-libraries/llm-post-training` |
| 备份根 | `D:/agent-data/backups/paper-libraries/llm-post-training` |
| Obsidian Vault | `D:/obsidian/data/paper-knowledge-engine/llm-post-training` |

路径由现有机器根配置与方向库标识派生。本节描述实施目标，本轮不创建这些运行目录。

本库拥有独立 SQLite、Archive、运行记录、冻结集合、水位、锁、配额、PDF 根、Vault 和发布回执。四个方向共用程序与机器资源，不共用方向状态；共享 GPU 的资源限制仍按现有引擎约束执行。

| 自动日期起点 | `2026-01-01` | 与现有方向库一致；历史基础论文另行人工补充 |
| 增量重叠窗口 | 48 小时 | 沿用现有恢复与去重机制 |
| Current 总上限 | 180 篇/次 | 是单次处理上限，不是全库容量或必须填满的目标 |
| Track 配额 | 每个 Track 10 篇 | 当前选篇器先按目标配额分配，空额可以外溢；不是每类绝对硬上限 |
| Weekly 总上限 | 18 篇/次 | `weekly` 是既有增量模式名称 |
| 首轮真实试运行 | 5–10 篇 | 先验证质量与完整链路，再扩大处理规模 |
| 历史基础候选清单 | 20–30 篇 | 人工选择并去除已有资料，不自动抓取 |
| 自动调度 | 首期不注册定时任务 | 保留手动 current/weekly 能力；定时运行作为后续独立配置项 |

实施约束补充（2026-09-08）：现有 `weekly_schedule.enabled` 同时控制手动 `weekly` 执行，设为 `false` 会直接返回 `disabled`。因此采用 `enabled: true` 保留增量执行能力，以不注册 Windows/Codex 定时任务落实“首期关闭自动调度”。调度描述符存在不代表定时任务已安装；此处不改变共享引擎语义。

相同论文多 Track 命中不重复占用论文总数。沿用共享计数口径，区分候选、规则通过、新版本、成功归档和成功发布，避免把命中次数当作论文数量。

## 9. Obsidian 交付形态

```text
llm-post-training/
  Evidence/              引擎托管
    papers/              论文资料、来源链接、PDF、正文及资源
    indexes/             authors、categories、tracks、years
  Knowledge/             后续人工维护
```

Evidence 使用现有 v3 结构，不新增算法排名、实验结论或训练参数的自动抽取字段。PDF、解析正文、来源版本与页级引用构成证据基础。

人工 Knowledge 可逐步形成以下页面，但不作为首期自动生成交付：

- 后训练学习路线与术语地图。
- SFT、偏好优化、强化学习和蒸馏的比较。
- 数据、奖励与评测设计清单。
- 推理训练、Agent 训练与多模态训练专题。
- 失败模式和复现记录。

人工方法卡建议记录：研究问题、基座模型、学习目标、更新对象、训练数据、反馈来源、采样与优化流程、资源成本、评测协议、主要结果、负面结果、适用条件及出处。论文未报告的信息标记“未报告”，不按经验补写；模型生成的总结不得冒充原文证据。

## 10. 建设阶段与验收

### 阶段一：方向接入与规则校准

交付四文件配置、方向说明及必要的配置/筛选回归样例。

- CLI 能发现并显式选择 `llm-post-training`，以 paper 库加载。
- 四份配置中的 18 个 Track 一致，生成 36 个日期分片，所有 Track 有 PDF 映射。
- 正例、负例和边界例覆盖第 6 节要求；不能仅验证新配置字段存在。
- 运行根和状态隔离验证覆盖四个方向；原有方向保持可用。

### 阶段二：小规模资料验收

交付 5–10 篇真实论文的端到端试运行结果，以及候选质量抽查记录。

- 论文能够完成 PDF → MinerU → Archive → Evidence，并在 Obsidian 中打开正文、PDF、图片和索引链接。
- 重点检查公式、表格和页级引用的可用性；解析问题应明确记录，不能把“有 Markdown 文件”等同于内容正确。
- 重复发布不产生重复资料；中断恢复保持冻结选篇；失败可从已有阶段恢复。
- 手工导入不会推进 arXiv 水位；Evidence 发布不创建或覆盖人工 Knowledge。

候选质量另抽查 20–40 篇通过规则的唯一论文，按明确规则选取跨 Track 样本并保存样本 ID。建议的初期相关率门槛为至少 85%（确实符合第 3 节范围的样本数 / 抽查总数）；不足 20 篇时报告实际数量，不宣称达到整体质量门槛。这个比例是设计验收目标，不是已测结果，也不代表对全体论文的召回率。

### 阶段三：形成首期资料库

在试运行通过后，按 Current 上限开展首轮建设，整理历史基础候选并按需人工导入。

- 交付实际收录数量、主题分布、误收/漏收样例及失败清单。
- 目标是主题覆盖合理、证据可追溯，不为填满 180 篇而放宽筛选。
- 当前时间窗口没有合格论文的 Track 明确标记覆盖缺口，历史补充另行记录。

### 阶段四：增量维护

手动运行 `weekly` 验证新增版本、重叠窗口与恢复机制，再根据实际耗时和主题产出调整配额。自动调度的频率、时间和资源错峰在需要启用时确定；本方案不创建定时任务。

## 11. 首期范围约束

- 建设论文知识库，不搭建模型训练平台，不启动训练实验。
- 保留现有引擎、Archive v2 和 Evidence v3，避免复制后训练专用采集/解析/发布模块。
- 保存论文证据，不自动下载训练集、权重或执行论文代码。
- 不新增自动问答、向量检索、LLM 摘要或自动方法推荐。
- Benchmark 方法论文可以收录；不建设排行榜，不自动运行 Benchmark，也不存储完整测试集。
- 不将纯推理优化、通用预训练或所有 Agent 工程主题无边界地并入本库。
