# DataWatch 使用说明

## 1. 作用与边界

DataWatch 获取并归档以下四个 Hugging Face 仓库的原始文件：

1. VaidhyaMegha/regulatory-affairs-kg：器械监管知识图谱，包含 nodes/、edges/ 下的 CSV 和图快照。仓库 README 中的节点、关系统计是图谱元素数量，不等于器械数量。
2. wapplewhite4/fda-recall-intelligence：FDA 召回智能分析的公开 Parquet 样本。它是样本文件，不应描述为 FDA 全量召回库。
3. electricsheepafrica/pharmaceutical-procurement-pricing：三个采购场景的模拟药品采购数据，包含 CSV、校验报告 PNG 和生成脚本。
4. diamondgible2/Hospital-Resource-And-Patient-Management-Dataset：合成医院运营数据，包含库存、占用、患者、房间、库房、工具和用户 CSV。

这些数据已是结构化表格或图谱文件。CSV、Parquet 和图快照不需要 OCR 或版面解析，因此本项目不安装、不启动、不调用 MinerU，也不会把文件改写为 Excel。
本项目只核对来源文件清单、大小和 SHA-256；README 中发布方声明的记录数、节点数或召回数不作为本程序的记录数核验结果。

## 2. 环境准备

需要 Bun 1.4.0 或更高版本，并能访问 huggingface.co。在 PowerShell 中执行：

~~~powershell
Set-Location D:\agent-data\backend\projects\datawatch-data
bun install --frozen-lockfile
Copy-Item config\paths.example.json config\paths.local.json
bun run typecheck
bun test
~~~

config/paths.local.json 是本机配置，不提交到 Git。六个字段必须是绝对 Windows 路径；原件、状态、Obsidian 和备份四个运行资料根必须互不嵌套：

| 字段 | 默认位置 | 内容 |
| --- | --- | --- |
| projectRoot | D:\agent-data\backend\projects\datawatch-data | 项目代码根 |
| paperEngineRoot | D:\agent-data\backend\projects\paper-knowledge-engine | 共享 HTTP 运行时和可选代理配置 |
| originalRoot | D:\paper\DataWatch | Hugging Face 原始文件 |
| dataRoot | D:\agent-data\data\datawatch-data | 清单、任务记录和临时工作目录 |
| vaultRoot | D:\obsidian\data\datawatch-data | Obsidian 副本 |
| backupRoot | D:\agent-data\backups\datawatch-data | 备份包和 manifest |

如果网络必须经过代理，可在 paperEngineRoot\config\machine.local.yaml 的 network.http_proxy 填写已运行的 HTTP(S) 代理。DataWatch 只读取这个共享网络设置，不读取 MinerU 配置。

## 3. 启动菜单

从任意工作目录使用绝对入口启动：

~~~powershell
bun D:\agent-data\backend\projects\datawatch-data\src\cli.ts
~~~

一级菜单选择一个数据集或“获取全部数据集”。进入数据集菜单后可以查看来源、运行或恢复任务、查看版本状态、校验副本、发布 Obsidian、创建备份、探测来源和切换数据集。菜单不会询问抽样数量；本期每个来源都获取固定 commit 下的全部公开仓库文件。

## 4. 非交互命令

~~~powershell
Set-Location D:\agent-data\backend\projects\datawatch-data

bun src\cli.ts sources list --format json
bun src\cli.ts source show --dataset fda-recalls --format json
bun src\cli.ts source probe --dataset hospital-resources --format json

bun src\cli.ts run-task --dataset regulatory-affairs --format json
bun src\cli.ts run-task --all --format json

bun src\cli.ts status --format json
bun src\cli.ts status --dataset fda-recalls --format json
bun src\cli.ts config show --format json
bun src\cli.ts verify --format json
bun src\cli.ts verify --dataset hospital-resources --format json
bun src\cli.ts catalog build --format json

bun src\cli.ts backup create --format json
bun src\cli.ts backup verify --path D:\agent-data\backups\datawatch-data\backup-YYYYMMDDHHMMSS.zip --format json
bun src\cli.ts backup restore-smoke --path D:\agent-data\backups\datawatch-data\backup-YYYYMMDDHHMMSS.zip --format json
~~~

source probe 只读取来源版本和文件树，不下载正文。run-task 先固定版本，再枚举和下载文件。status 查看任务与本地版本，verify 对原件及 Obsidian 副本逐文件计算大小和 SHA-256。

## 5. 文件位置与格式

原件目录形如：

~~~text
D:\paper\DataWatch\<dataset-id>\
  README.md
  nodes\submission.csv
  ...
~~~

机器清单形如：

~~~text
D:\agent-data\data\datawatch-data\
  <dataset-id>\manifest.json
  versions.json
  runs\<run-id>.json
  work\downloads\...
~~~

Obsidian 副本形如：

~~~text
D:\obsidian\data\datawatch-data\
  indexes\overview.md
  <dataset-id>\dataset.md
  <dataset-id>\manifest.json
  <dataset-id>\raw\...
  .datawatch-assets.json
~~~

监管知识图谱和采购、医院数据中的 CSV 可以直接用 Excel、Python pandas 或其他表格工具打开。召回数据的 Parquet 需要 pandas、Polars、DuckDB 或其他 Parquet 阅读器；如需人工查看，可以在下游工具中导出副本，DataWatch 本身保持发布方原始格式。

## 6. 版本、恢复与校验

每次任务先请求来源当前完整 commit SHA，并把已校验的原件、机器状态和 Obsidian 副本作为该数据集的当前快照保存。任务清单记录来源、版本、文件数、大小、SHA-256 和阶段状态；dataRoot\versions.json 集中保留版本元数据。网络中断或进程退出后，再次运行相同命令会继续未完成任务；已经存在且大小、哈希匹配的文件会跳过。来源出现新 commit 时先备份旧原件，再替换当前快照；不保留独立 SHA 目录。

下载采用 .part 临时文件和有限重试。文件大小不符、哈希不符、来源重定向不在白名单或文件路径不安全时，当前文件失败并记录错误；批量任务会继续其他数据集，最后返回失败汇总。修复网络或配置后重新运行即可。

执行 catalog build 会复制原始文件到 Obsidian 并生成带 generated_by: datawatch-data 的索引和数据集卡片。已有同名用户笔记不会被覆盖；已生成文件被手工改动后，发布会报告冲突并停止。verify 可用于恢复后复核。

## 7. 备份

备份是独立操作，不会进入数据获取任务阶段：

~~~powershell
bun src\cli.ts backup create --format json
~~~

备份包包含原件、机器记录和 Obsidian 副本。压缩包和同名备份清单直接放在备份根目录，例如 backup-YYYYMMDDHHMMSS.zip 和 backup-YYYYMMDDHHMMSS.manifest.json。使用 backup verify 检查 ZIP、条目集合及每个文件的 SHA-256；backup restore-smoke 在不写入目标目录的情况下验证可解压条目和总字节数。实际恢复时应先准备空的目标根，再调用代码接口 restoreBackup，目标中已有不同字节的文件会被拒绝；旧版备份仍可校验和恢复。

## 8. 许可与使用提醒

监管数据来自 openFDA，来源说明为美国政府公开领域；FDA 召回仓库声明 CC BY 4.0；采购仓库声明 CC BY 4.0 但数据为模拟记录；医院仓库说明可用于研究和教育，未声明标准 SPDX 许可证，配置将其对外再分发标为 unknown。使用或发布任何数据集时应保留各仓库 README、许可和来源链接。

本项目只负责确定性获取和完整性校验。它不提供医疗结论、不执行数据合并、不生成价格或状态变动、不实现问数 Agent，也不对来源数据的业务含义作额外保证。

## 9. 常见错误

| 错误 | 处理 |
| --- | --- |
| PATH_NOT_ABSOLUTE | 检查 config/paths.local.json 的六个路径是否为绝对 Windows 路径。 |
| PATH_ROOTS_OVERLAP | 不要把一个数据根放在另一个数据根内。 |
| SOURCE_NOT_CONFIGURED | 检查 config/sources/ 是否保留四份 JSON，且数据集 ID 正确。 |
| RESEARCH_TIMEOUT 或 RESEARCH_TRANSPORT_FAILED | 检查网络或共享代理，随后重新运行任务。 |
| RESEARCH_REDIRECT_REJECTED | 先运行 source probe；若来源使用了新的官方 CDN，需要更新来源白名单并重新校验。 |
| FILE_HASH_MISMATCH | 删除对应 .part 文件后重试；不要手工修改原件。 |
| CATALOG_USER_FILE_CONFLICT | 恢复被改动的生成文件，或把笔记移到生成文件之外后再执行发布。 |
| PROJECT_BUSY | 等待另一个 DataWatch 操作结束；不要手工删除仍在运行的锁文件。 |
